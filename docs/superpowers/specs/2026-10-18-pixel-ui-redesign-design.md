# 像素化 介面改版與自動選模型 設計規格

日期: 2026-10-18
狀態: 已實作(2026-10-18), 等使用者實測

## 1. 背景

- 使用者回饋: 像素化介面不直觀; 直接轉換不需要選模型; 眼睛只能標一個
- 2026-10-17 實驗(holy_knight, 8 個 fal 模型 × Gemini 建議的 32×48 / 64×96 / 88×120):
  - 小尺寸: 直接轉換最好(AI 畫不出那麼粗的格子, 縮完很雜)
  - 中大尺寸: Nano Banana Pro、GPT Image 2 最好; Kontext 會改色, 不優
  - 實際格數: GPT Image 2 在 64 以上偏差 5~10% 內; Nano Banana Pro 要 32×48、64×96 都畫約 81×112, 88×120 才剛好(偏差 1~2%)
- 使用者決定: 不讓使用者選模型, 選 AI 重畫時依尺寸自動選

## 2. 右側設定

```
轉換方式  [ 直接轉換(免費) | AI 重畫(付費) ]
尺寸      [ 指定格數 | 自動尺寸 ]
          指定格數: 拖拉格子(共用), 下方顯示 寬W×高H格 / 實際尺寸
          自動尺寸: [請 AI 建議尺寸] → 2~3 張建議卡(尺寸、色數、理由), 點一張 = 套用到格數與色數
── 直接轉換 ──                 ── AI 重畫 ──
色數 / 加外框 / 眼睛清單       使用模型: 依尺寸自動(顯示名稱與原因)
[直接轉換]                     色數 / 補充描述 / 候選張數
                               [AI 重畫] 約 X 美元
```

- 兩種方式共用同一組格數與「指定格數 / 自動尺寸」切換; 自動尺寸套用建議後, 格子同步顯示該尺寸
- 自動尺寸: 用 Gemini 2.5 Flash 看來源圖(流程節點用上游輸出), 每次 < 0.01 美元, 要 FAL_KEY; 建議只存在畫面上(換來源就清掉)
- AI 重畫的長邊 ≤ 48px 時顯示提示「這個尺寸直接轉換通常比較好」, 但仍可畫
- 拿掉舊的「自動尺寸 = AI 自己決定大小、可選 Kontext / Banana Pro」; 舊候選照常顯示與縮小

## 3. 自動選模型

| 長邊(像素) | 模型 | 每張約 |
|---|---|---|
| ≤ 96 | GPT Image 2(`openai/gpt-image-2/edit`, quality medium) | 0.06 美元 |
| ≥ 104 | Nano Banana Pro(`fal-ai/nano-banana-pro/edit`) | 0.15 美元 |

前後端同一條規則; 候選記下 `model`。

## 4. 眼睛(直接轉換)

- 可標多個, 最多 4 個。按「+ 標記眼睛」進入標記: 來源圖放大, 每拖一個圓多一個眼睛(只點不拖用預設大小), 可連續標, 按「完成」結束; 到 4 個自動結束
- 圖上的圓標號碼; 右側清單「眼睛 1 ×」可個別刪除
- 每個眼睛的虹膜色各自從原圖它的範圍取
- 設定 body 改成 `eyes: [{x, y, r}]`(0~4 個); 舊候選的 `eye` 單一欄位照常可縮

## 5. 中間區塊

- 「來源 → 候選 → 結果」不變
- 候選標籤統一「方式 · 實際像素尺寸」: `直接轉換 · 32×32`、`AI 重畫 · 64×96`; 舊的自動尺寸候選 `AI 重畫 · 自動尺寸`
- 結果卡片: 有「設為輸出」時放最上面且是主要按鈕; 匯出(原尺寸 PNG / 放大 ×8 / .gpl)縮成一列小按鈕

## 6. API

| 方法 | 路徑 | 說明 |
|---|---|---|
| POST | `/api/pixel/works/{name}/suggest` | 以作品來源圖建議尺寸 → `{sizes: [{cols, rows, colors, reason}]}` |
| POST | `/api/flows/{flow}/nodes/{id}/pixel/suggest` | 以上游輸出(裁透明、鋪白)建議; 上游沒輸出 400 |

- 建議解析: 寬高對齊到 8 的倍數(四捨五入)並限制在 8~128, 色數限制在 4~32, 去掉重複, 依面積小到大; 一個都解析不出來 → 400「AI 沒有給出尺寸建議」
- `POST .../candidates` 只接受指定格數(`mode` 省略或 `grid`), 忽略 `model`, 由後端依尺寸選; `mode: auto` 回 400
