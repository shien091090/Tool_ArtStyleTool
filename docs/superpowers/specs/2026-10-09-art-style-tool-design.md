# 美術風格探索工具 設計規格

日期: 2026-10-09
狀態: 已核可(2026-10-09)

## 1. 目的與範圍

AI 生圖的「AI 味」主要來自 AI 預設的上色方式(柔光、過多細碎漸層、塑膠高光)。本工具把一張圖拆成線條、色彩、光照等獨立的層, 每層用參數重新渲染, 讓使用者以人機協作的方式**探索並固定個人美術風格**, 未來用於各種 2D 遊戲。

- 目標: 探索風格, 不綁定特定遊戲; 先以 2D 為主
- 不處理: 造型上的 AI 味(比例、形狀簡化)。由使用者自行繪製造型, 或另外訓練 LoRA
- 成功標準: 同一份風格配方套到不同的圖上, 成品看起來像同一個人畫的

## 2. 整體流程

```
階段一 拆解: 有光影的成品圖 ──▶ 線稿、平塗圖、法線圖、區塊編號圖 (= 分層包)
                                     │
                              [檢查點: 使用者對照確認, 可重跑、改色、換成自己畫的]
                                     ▼
階段二 渲染: 分層包 + 風格配方 ──▶ 五層即時渲染 ──▶ 成品圖
```

- 標準輸入是**一張有光影的成品圖**
- 已有線稿或平塗圖的話, 可以在檢查點直接替換對應的層, 或略過階段一
- 輸出: 成品圖(PNG)、風格配方(JSON)

### 2.1 拆解順序(確保逐像素對齊)

三張圖必須逐像素對齊, 所以平塗圖不交給 AI 重畫, 改由線稿推導:

1. **法線圖**: fal.ai 上沒有專門的法線模型(2026-10 調查), v1 用 fal.ai 推**深度圖**, 再在本機換算成法線。這類模型沒用卡通上色的圖訓練過, 動漫風的法線會偏弱, 靠檢查點把關。品質較好的法線模型(StableNormal、Marigold 法線版)要自架, v1 不做
2. **線稿**: 用 fal.ai 的線稿抽取前處理器(候選: `lineart`、`teed`、`hed`、`pidi`), 只抽結構線, 忽略陰影邊緣。實作初期先拿使用者的圖比一輪, 決定預設值; 檢查點可以換模型重跑
3. **區塊編號圖**: 本機用線稿圍出封閉區塊, 每塊一個編號。演算法參考 LineFiller 的 trapped-ball 填色(MIT)。提供「補線縫」參數, 處理線條沒接起來、顏色漏到隔壁區塊的情況
4. **平塗圖**: 本機對每個區塊, 到成品圖中取代表色(去掉最亮與最暗的部分後取中位數)填滿。代表色可能殘留原圖光影, 不準就在檢查點手動改色。專門的去光影模型 v1 不用(見第 10 節)
5. **線條距離場**: 本機計算每個像素到線條中心的距離, 供渲染時即時調整線條粗細

fal.ai 只用於第 1、2 步, 每張圖只在拆解時呼叫一次。之後調整風格參數完全不連網。

## 3. 架構

```
瀏覽器(渲染段)                        本機伺服器(拆解段)
├ 拆解檢查頁                          ├ 呼叫 fal.ai: 法線、線稿
├ 渲染頁: WebGL2 五層渲染         ◀─▶ ├ 影像處理: 區塊、平塗、距離場
└ 對照網格                            └ 讀寫分層包與風格配方
```

| 部分 | 技術 |
|---|---|
| 前端 | Vite + TypeScript + 原生 WebGL2, 參數面板用 Tweakpane |
| 後端 | Python + FastAPI, 只監聽本機; 影像處理用 OpenCV |
| AI | fal.ai, 金鑰放在後端的環境變數, 不進前端 |

選本機伺服器的原因: 金鑰不能暴露在網頁裡; 區塊與距離場用 OpenCV 最省事, 運算輕, GTX 1650 這等級的電腦沒問題。拆解來源要寫成可替換的介面, 之後才能把個別步驟改成在本機跑。

## 4. 資料格式

### 4.1 分層包

一張圖一個資料夾, 放在 `packs/<名稱>/`:

| 檔案 | 內容 |
|---|---|
| `source.png` | 原始成品圖 |
| `line.png` | 線稿(白底黑線) |
| `line_dist.png` | 線條距離場 |
| `regions.png` | 區塊編號圖 |
| `flat.png` | 平塗圖 |
| `normal.png` | 法線圖 |
| `meta.json` | 尺寸、區塊數與各區塊代表色、各層來源(AI 產生 / 使用者替換)、建立時間 |

v1 限制輸入長邊最大 2048px, 超過自動縮小。

### 4.2 風格配方

`recipes/<名稱>.json`, 記錄五層參數, 與分層包無關, 可套用到任何分層包。帶 `version` 欄位以便日後升級格式。單一區塊的手動改色屬於分層包, 不存在配方裡。

## 5. 渲染五層

由下往上疊, 每層一個 fragment shader, 可以各自開關。

| 層 | 讀取 | 參數 |
|---|---|---|
| 1 色彩 | 平塗圖、區塊編號圖 | 色票(自動抽色 / 預設 / 手動), 區塊對應到色票, 色相、飽和、色溫 |
| 2 光照 | 法線圖 | 光源方向(畫面上拖點設定水平角與仰角), **色階數**(1 = 不打光, 2~3 = 卡通上色, 調高接近寫實), 陰影上色(壓暗 / 偏冷色), 環境光強度, 邊緣光開關 |
| 3 線條 | 線條距離場 | 粗細, 粗細變化(均勻 / 背光側加粗), 線色(純黑 / 取底下色塊的深色), 質感(乾淨 / 鉛筆 / 蠟筆), 抖動 |
| 4 特效 | 前三層結果、光照結果 | 網點(大小、角度、可限陰影區), 紙紋, 顆粒 |
| 5 濾鏡 | 整張成品圖 | 像素化(像素大小、抖色), 油畫感平滑, 色調映射, 暗角 |

前四層會讀分層包的資料, 因此能做「網點只上在陰影區」這類效果; 第五層只看整張成品圖。

shader 一律自己寫。效果串接的架構參考 pmndrs/postprocessing(Zlib), 卡通光照、邊緣光、油畫感平滑、抖色的演算法參考 lettier 的 3d-game-shaders-for-beginners 與 glfx.js 的寫法。

## 6. 介面

### 6.1 拆解檢查頁
- 上傳成品圖, 執行拆解, 顯示進度
- 原圖、線稿、平塗圖、法線圖四格並排, 可切換疊圖比對對齊
- 點區塊改色; 調整補線縫參數後重算區塊
- 單獨重跑某一步, 或上傳自己的圖替換某一層
- 確認後存成分層包

### 6.2 渲染頁
- 中央畫布, 右側參數面板按五層分組, 每層有開關
- 原圖 / 成品切換對照
- 配方: 存檔、讀取、另存
- 匯出 PNG

### 6.3 對照網格
- 把目前的配方同時套到多個分層包上, 縮圖並排
- 用途: 直接檢驗成功標準(換圖後還是同一個風格)

## 7. 錯誤處理

- 啟動時沒有 fal.ai 金鑰: 拆解頁明確提示怎麼設定, 渲染頁照常可用
- fal.ai 呼叫失敗或逾時: 顯示錯誤訊息, 可單步重試, 已完成的步驟結果保留
- 區塊漏色: 調補線縫參數重算, 或上傳修好的線稿
- 讀到舊版或欄位缺漏的配方: 缺的參數補預設值, 並提示使用者

## 8. 測試

- 後端影像處理(區塊、取色、距離場): 用程式畫的簡單測試圖做單元測試, 結果可以精確驗證
- fal.ai 呼叫: 測試時用假回應取代
- 配方: 存檔再讀取, 內容一致; 舊版配方補預設值
- 渲染: 準備一組樣本圖, 人工目測; 每層 shader 開關切換後不報錯
- 驗收: 5 張不同的圖 × 3 份配方, 用對照網格確認風格一致

## 9. v1 不做

- 不同區塊各套不同風格
- 匯出分層包與 shader 給遊戲引擎用
- 水彩暈染這類筆觸模擬
- 拆解步驟改在本機跑
- 自架法線模型(StableNormal、Marigold 法線版)
- 去光影模型
- 造型處理(LoRA 等)
