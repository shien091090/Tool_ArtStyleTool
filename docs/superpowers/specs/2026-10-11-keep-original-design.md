# 保留原圖 設計規格(D 組)

日期: 2026-10-11
狀態: 已核可(使用者同意方向並授權寫完直接實作)
前置: v1 規格、B 組(拆解品質)、C 組(風格效果擴充)

## 1. 問題與原則

目前渲染一開始就把原圖換成「平塗 + 線稿」, 還沒調任何參數就跟原圖差很多。平塗本質上丟掉了光影、漸層、紋理、原本的線條, 拆得再好也回不去。

新原則: **不動任何參數時, 渲染結果就是原圖; 每個參數都是從原圖往某個風格偏移。**

## 2. 做法: 原圖細節

在 OKLab 色彩空間定義:

```
原圖細節 = 原圖 − 平塗(取色當下的顏色)
原圖細節 = 原圖光影(區塊內模糊後的細節) + 原圖紋理(其餘)
```

渲染時(OKLab):

```
輸出 = 卡通光照結果 + (新平塗 − 卡通光照結果) × 保留光影
       + 保留光影 × 原圖光影
       + 保留紋理 × 原圖紋理
```

兩個保留都為 1 且沒改色時, 輸出 = 原圖。改色時細節疊在新顏色上, 等於幫原圖重新上色。

### 2.1 原圖光影的算法(修實驗中的糊與光暈)

只在同一個區塊內模糊, 並排除線條像素(正規化卷積: 區塊內細節 × 遮罩的模糊 ÷ 遮罩的模糊)。線條像素取同區塊的模糊值。模糊半徑 = 長邊 / 60。這樣光影不會跨區塊暈開, 也不會把線條暈成髒污。

### 2.2 精度

原圖紋理不存檔, 渲染時即時算: `原圖 − 平塗取色 − 原圖光影`。因此不論原圖光影存檔時量化多少, 兩個保留都為 1 時一定還原原圖(誤差只來自 GPU 浮點, ≤ 2/255)。

### 2.3 取色顏色與編輯顏色分開

分層包 meta 的區塊顏色分成:
- `sampled`: 拆解時從圖取出的顏色, 只用來算原圖細節, 不會被改
- `colors`: 可編輯的顏色(檢查點點區塊改色改這個), 是渲染的「新平塗」

舊分層包沒有 `sampled` 時以 `colors` 代替。這樣在檢查點把某塊改成紅色, 兩個保留都在 1 時也看得到變紅(細節疊在紅色上)。

## 3. 拆解端

- 新圖層 `shade.png`(原圖光影), 在平塗之後算, RGB 編碼: L × 127 + 128、a/b × 300 + 128
- 新步驟 `shade`: 需要區塊; 有線稿時排除線條
- 相依: `regions → shade`、`delight → shade`(取色來源變了, sampled 會變)
- 渲染端缺 `shade` 時以 0 代替(原圖細節全部算進紋理), 仍滿足「預設 = 原圖」

## 4. 渲染端

- 新的配方區段 `keep`: `enabled`、`shade`(保留原圖光影 0~1)、`texture`(保留原圖紋理 0~1); 面板放在最上方「保留原圖」
- 光照 pass 重排: 先算色階明暗(陰影色、亮面染色) → 依保留光影與原圖細節混合 → 再加上高光、補光、邊緣光、環境遮蔽(這些是額外加上去的效果, 不會被保留光影吃掉)
- 新增原始取色表(`sampled` 的 256x256 表)給 shader 算原圖細節
- 新版預設配方: 保留光影 1、保留紋理 1、**線條預設關閉**(原本的線條已在紋理裡)

## 5. 配方格式升級

- `version` 升為 2
- 讀到第 1 版(或沒有 version)的配方: `keep` 補成 `{ shade: 0, texture: 0 }`、`lines.enabled` 預設視為開啟, 外觀與以前完全相同, 不跳提示
- 六份起始配方原本是在「不保留」的前提下調的: 明確設為保留 0/0、線條開啟; 水彩與賽璐璐改為保留部分紋理, 看起來更自然
- 顯示規則: 保留光影 = 1 時, 陰影上色、陰影顏色、陰影強度、亮面顏色、亮面染色沒有效果, 隱藏

## 6. 測試

- 後端: 原圖光影只在區塊內模糊(邊界兩側互不影響)、排除線條、line 不存在時也能算; `sampled` 在改色後不變; 舊包缺 `sampled` 的退回
- 前端: 第 1 版配方遷移(keep 0/0、線條開啟、不提示); 新預設 keep 1/1、線條關閉; 起始配方正規化無修正; 新顯示規則
- 瀏覽器: 預設配方渲染結果與原圖逐像素比較, 最大誤差 ≤ 2/255(怪物與騎士); 改色、拉低保留的視覺檢查

## 7. 不做

- 檢查點顯示原圖光影圖層(之後需要再加)
- 原圖紋理再細分(例如線條與花紋分開保留)
