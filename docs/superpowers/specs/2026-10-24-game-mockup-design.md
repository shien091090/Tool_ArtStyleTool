# 遊戲示意與素材庫

日期: 2026-10-24。接在節點流程編輯器第 4 期(移除舊頁籤)之後。

## 為什麼

使用者想組合出不同種類遊戲的 GamePlay 示意圖(類似垂直切片), 用來探索美術風格: 先依遊戲視角定出畫面架構, 擺上物件, 再請 AI 依目前風格畫成一張像真的遊戲截圖。

2026-10-24 兩輪實驗(暫存資料夾, 結論以此為準)確認可行:

1. **灰盒交給 AI 畫整張**: 有文字標籤的灰盒 + 風格描述送 GPT Image 2 edit(medium, 約 0.06 美元/張), 構圖、物件都照灰盒, 標籤字會清掉。Nano Banana Pro 會把標籤字畫進圖, 不用。
2. **灰盒配色影響小**: 物件是什麼主要看標籤; 顏色只會帶到小物件(敵人顏色)與整體氣氛(大片底色)。灰盒預設灰色, 顏色只當提示。
3. **已擺素材 + 灰盒混合**: 把從結果圖截下、去背的素材擺回灰盒, 其餘灰盒 AI 會照素材的風格補, 整張看起來是同一款遊戲。GPT Image 2 整張重畫時幾乎不動素材, 重畫後把素材貼回原位最好(比遮罩只畫灰盒的完成度高)。
4. 已知問題(實作時用指令處理): 有素材時大片背景(天空、遠山)會被當成成品不畫; 斜角俯瞰的小角色會不見。

使用者想要的循環:

> 灰盒 → AI 畫整張 → 在結果圖上框選喜歡的物件, 截下收進素材庫 → (可選)素材送進平面圖流程改風格/像素化, 產生派生素材收回素材庫 → 新場景部分灰盒換成素材庫的圖, 其餘灰盒請 AI 照這些素材的風格補

## 目標

1. 工具分三個頁籤: **平面圖**(原「流程」節點編輯器, 改名)、**遊戲示意**(新)、**素材庫**(新)。
2. 素材庫: 收藏自己匯入的圖、平面圖節點輸出、遊戲示意截下的物件; 原圖與派生歸在同一組; 可掛遊戲示意標籤(視角、類型)。
3. 遊戲示意: 選畫面架構 → 擺灰盒/素材/地面 → AI 畫整張 → 框選截素材。
4. 灰盒場景可以從遊戲截圖匯入(AI 認物件), 也可以從使用者自己的遊戲匯入(記錄畫圖動作)。

## 非目標

- UI/HUD(血量、分數、選單)第一版不做, 只畫純遊戲畫面; 之後再擴充。
- 3D 遊戲視角。
- 素材庫頁籤裡不放「送去平面圖」之類的跳轉按鈕: 要派生, 使用者自己到平面圖用圖片輸入節點挑素材庫的圖。
- 匯入素材庫時不自動去背(有需要自己跑平面圖的去除區塊)。遊戲示意框選截素材則**要**自動去背。
- AI 畫出來的整張示意圖不收進素材庫, 只留在場景的候選裡。
- 動畫、可遊玩。

## 分期

每期先寫細規格再實作, 做完讓使用者實測才進下一期(同節點流程編輯器的做法)。

| 期 | 內容 |
|---|---|
| 1 | 頁籤列(平面圖、素材庫)、素材庫、平面圖的圖片輸入可選素材庫、節點輸出存到素材庫、派生歸組、標籤 |
| 2 | 遊戲示意核心: 五種畫面架構、灰盒/素材/地面編輯、風格設定、AI 畫整張並貼回素材、候選、框選截素材(自動去背) |
| 3 | 從截圖匯入灰盒: AI 看圖列出物件名稱與位置框, 轉成灰盒 |
| 4 | 從自己的遊戲匯入灰盒: 記錄遊戲畫圖函式的繪製範圍 |

第 3、4 期細節(匯入時怎麼決定畫面架構、遊戲從哪裡載入等)做到那期再和使用者討論。

## 共通: 視角與類型標籤

素材可以掛「遊戲示意標籤」, 沒掛的就是一般素材(素材庫的「未分類」)。沒選任何視角的素材都算未分類, 即使有選類型。

- **視角**(可多選): 橫向卷軸、縱向卷軸、俯瞰、斜角俯瞰、平面。內部代號 `side`、`vertical`、`topdown`、`iso`、`flat`。
- **類型**(單選, 可不選): 地形、背景、角色、敵人、道具、建築、景物、其他。(類型清單是實作者的決定, 可以調)
- 標籤的三種掛法: 匯入時選(可略過); 素材庫裡補標/修改; 第 2 期在遊戲示意擺未分類素材時自動掛上該場景的視角。
- **派生素材沿用原圖的標籤**(存入當下複製一份, 之後各自獨立可改)。

## 第 1 期: 頁籤與素材庫

### 頁籤列

- 頂端恢復頁籤列: 「平面圖」「素材庫」(第 2 期再加「遊戲示意」)。fal 餘額與進度列照舊。
- 網址: 平面圖沿用 `#/flow`(舊書籤不失效), 素材庫 `#/library`; 其他網址轉 `#/flow`。
- 介面上所有「流程」字樣不改(流程是平面圖頁籤裡的單位, 例如「新流程」「刪除流程」), 只改頁籤名稱。README 對應改寫。

### 素材資料

存在 `data/library/`(不進版控, .gitignore 加一行):

```
data/library/
  <素材編號>/
    image.png      # 素材圖(RGBA, 不變; 素材圖本身建立後不能改, 只改說明資料)
    asset.json
```

`asset.json`:

```json
{
  "id": "a12",
  "name": "像素樹",
  "created": "2026-10-24T15:00:00",
  "parent": "a3",
  "source": {"kind": "flow", "flow": "樹改水彩", "node": "n4", "rev": 2},
  "tags": {"views": ["side"], "type": "景物"}
}
```

- `id`: 後端配發(`a` + 遞增數字), 不重複使用。
- `parent`: 直接的原圖編號, 沒有就是 null。**組** = 沿 parent 一路往上到頂的那張(根)加上它所有子孫。
- `source.kind`: `import`(自己匯入, 記原檔名)、`flow`(平面圖節點輸出, 記流程名、節點、版本)、`mockup`(第 2 期遊戲示意截下, 記場景與候選)。
- 圖片大小沿用 `config.MAX_SIDE` 上限。

### 刪除素材

- 刪除只刪那一張; 它的子素材改掛到它的 parent(沒有 parent 就變成新的根)。需要確認對話框。
- 平面圖裡用過這張的圖片輸入節點不受影響(輸入節點選圖時已經把圖複製成自己的輸出)。

### 素材庫頁籤

- **左側篩選**: 全部 / 五種視角 / 未分類; 類型篩選(下拉, 預設全部); 名稱搜尋。
  - 篩選以「張」為準, 但一組只要有任一張符合, 整組都顯示, 不符合的那幾張淡化。(實作者可改成更好懂的呈現, 原則是原圖和派生看得到彼此)
- **主區**: 一組一列(或一張卡片), 根在最前, 後面依建立時間排派生; 派生的派生也在同一組, 縮圖上標出它從哪張來(例如縮圖角落的小字「← 像素樹」或縮排, 實作者決定)。
- **點一張** → 右側詳細: 大圖(透明格底)、名稱(可改)、標籤(視角多選、類型單選, 可改)、來源說明(「自己匯入: tree.png」「平面圖 樹改水彩 / 改風格節點 第 2 版」)、原圖是哪張(可點過去)、下載 PNG、刪除。
- **匯入**: 「匯入圖片」可多選檔案; 匯入前可選一次標籤套用到這批(可略過)。名稱預設取檔名(去副檔名)。
- 頁籤裡沒有其他跳轉按鈕(見非目標)。

### 平面圖: 圖片輸入選素材庫

- 圖片輸入節點變成兩種來源: 「上傳圖片」(照舊) 與「從素材庫選」。
- 從素材庫選: 打開挑選視窗(同素材庫的篩選與縮圖, 只能選一張), 選好立刻把該素材圖複製成這個節點的輸出; 節點參數記 `{"source": "<素材名稱>", "asset": "<素材編號>"}`。上傳時參數不帶 `asset`。
- 後端: 節點輸出 API 加一個表單欄位 `asset`(素材編號), 有它時不需要檔案; 只允許圖片輸入節點用。
- 素材後來被刪除, 節點輸出照舊; 之後從這條流程存回素材庫時就當成沒有原圖(parent = null)。

### 平面圖: 節點輸出存到素材庫

- 每個有輸出的節點都可以存: 節點右鍵選單加「存到素材庫」, 節點設定畫面右上「下載輸出 PNG」旁也加同一個按鈕。沒有輸出時停用。
- 按下跳出小對話框: 名稱(預設「流程名 節點種類」, 例如「樹改水彩 改風格」)、顯示「派生自: 像素樹」或「獨立素材」, 確定後存入, 顯示「已存到素材庫」。
- **判斷原圖**: 從這個節點沿主圖輸入(不含改部位的素材接點)一路往上找到圖片輸入節點; 該節點參數有 `asset` 且素材還在 → parent = 它, 標籤複製它的; 否則 parent = null、沒有標籤。
  - 圖片輸入節點自己按存到素材庫且它來自素材庫: 等於複製一張, 照同規則記成派生(實作者可改成提示「這張已經在素材庫」)。
- **過期的輸出不能存**(我的決定, 避免歸錯組): 這條主圖輸入鏈上任一節點是橘燈(上游改過還沒重新產生, 依 `rev`/`inputRev` 判斷), 存到素材庫停用並提示「上游改過了, 先更新輸出再存」。這樣往上找到的圖片輸入節點一定就是這張輸出真正的來源。
- 同一個輸出可以重複存(每次都是新素材); 不做重複偵測。

### API(建議, 實作者可調)

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/api/library` | 全部素材的 asset.json 清單 |
| POST | `/api/library` | 匯入(多檔 + 可選標籤) |
| GET | `/api/library/{id}/image` | 素材圖 |
| PATCH | `/api/library/{id}` | 改名稱、標籤 |
| DELETE | `/api/library/{id}` | 刪除(子素材改掛) |
| POST | `/api/flows/{name}/nodes/{nid}/to-library` | 節點輸出存到素材庫(後端判斷原圖), 帶名稱 |

### 測試重點

- 後端: 匯入/改名/改標籤/刪除; 刪除中間那張子素材改掛; 從素材庫設定圖片輸入; 存到素材庫的原圖判斷(多層節點、改部位素材接點不算、素材已刪除、上傳來源); 標籤沿用。
- 前端: 分組與篩選邏輯(單元測試)、型別檢查、建置。

## 第 2 期: 遊戲示意核心(方向已定, 細節到那期再寫)

- **場景**: 選畫面架構新增; 存「架構 + 物件 + 風格設定 + 候選圖」, 存在 `data/mockups/<場景>/`。
- **五種畫面架構**: 橫向卷軸、縱向卷軸(直式 9:16)、俯瞰(方格)、斜角俯瞰(2:1 菱形格)、平面(卡牌/棋盤); 其他為橫式 16:9。每種帶一組預設灰盒(參考實驗的灰盒草稿), 可改可刪, 也可從空白開始。
- **物件**:
  - 灰盒: 有標籤的方塊(斜角俯瞰是可調高度的立體方塊); 預設灰色, 可上色當顏色提示; 標籤中英都可, 送 AI 時要讓它看得懂。
  - 素材: 從素材庫擺入, 拖曳、縮放、左右翻轉、前後順序; 擺入未分類素材會自動掛上該場景視角。
  - 地面: 俯瞰、斜角俯瞰、平面是格子地圖, 筆刷塗每格的地形標籤(草地、水、道路…); 橫向/縱向卷軸的地面當一般灰盒擺。
  - 不做: 旋轉、多選對齊、UI。
- **風格設定**: 風格描述文字、參考圖(可多張), 兩種都可選填, 跟著場景存。
- **畫圖**: GPT Image 2 edit(medium), 一次 1~4 張; 送出「灰盒 + 素材合成的圖 + 參考圖 + 指令」; 指令逐一列出灰盒物件、明說背景也是佔位、要求不畫標籤字、已完成的素材保持不變並以它們的風格補其餘。畫完把素材以原位置貼回, 結果加入候選。遮罩只畫灰盒(GPT Image 2 的 mask)可留作備案。
- **截素材**: 在候選圖上框選 → SAM 3 依框去背(挑框內面積最大的遮罩, 約 0.005 美元) → 存進素材庫, `source.kind = mockup`, 標籤 = 場景視角 + 依灰盒推測的類型(可改), 名稱預設為框到的灰盒標籤。
- 付費按鈕照工具慣例(金色 + 價錢)。

## 第 3 期: 從截圖匯入(方向)

上傳任一遊戲截圖(使用者自己的或市售遊戲), 看圖 AI 回傳物件名稱與位置框, 轉成灰盒場景, 使用者再修。框只求大概, 重疊小物件可能漏。約 0.01 美元/次。

## 第 4 期: 從自己的遊戲匯入(方向)

`E:\Project\Game` 下的遊戲都是 Canvas 2D 程式繪圖(不是 SVG 檔), 共同慣例: `art/art.js` 定義全域 `window.Art`, 一組 `draw*` 函式依狀態畫圖。做法: 載入遊戲, 包住 `window.Art` 的每個 `draw*` 函式記錄這次呼叫畫到的範圍(追蹤畫布變換與路徑範圍), 使用者玩到想要的畫面按「擷取」, 把那一幀的呼叫轉成灰盒(函式名轉中文標籤)。只適用遵守這個慣例的遊戲。
