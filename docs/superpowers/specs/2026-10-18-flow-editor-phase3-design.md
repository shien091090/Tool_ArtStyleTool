# 節點流程編輯器 第 3 期: 改風格節點 設計規格

日期: 2026-10-18
狀態: 已實作(2026-10-18), 等使用者實測

## 1. 目標

流程多一種節點「改風格」`style`: 把拆解檢查與渲染包成一個節點。來源是上游輸出, 節點裡先拆解(分層), 再用配方渲染, 渲染結果按「設為輸出」成為節點輸出。拆解檢查、渲染頁籤照常可用, 資料各自獨立(節點的分層包放在流程資料夾裡, 不會出現在分層包清單)。

## 2. 節點

- 標籤「改風格」, 有輸入接點, 要花錢(拆解要呼叫 AI; 上游換圖只亮過期, 不自動重跑)
- 資料: `data/flows/<流程>/nodes/<id>/` 就是一個分層包(meta.json + 各層 PNG), meta 另記 `inputRev`
- 輸出參數記 `recipe`(設為輸出時的完整配方), 下次打開沿用
- 刪節點或改種類時整個資料夾一起刪(沿用第 1 期)

## 3. 編輯面板

- 打開時還沒有分層包且上游有輸出 → 自動用上游輸出建立(免費; 透明處裁掉再鋪白底, 同改部位)
- 上游沒有輸出 → 顯示「上游還沒有輸出」
- 分層包的 `inputRev` 跟上游版本不同 → 黃色提示「上游已更新」+「改用新的上游圖」(確認後重建分層包, 需要重新拆解)
- 上方兩個頁籤「1 拆解」「2 渲染」:
  - 還沒拆解完(不能渲染)時預設在拆解, 渲染頁籤顯示「先到拆解按全部拆解」; 拆解完預設在渲染
  - 拆解: 同拆解檢查頁, 拿掉建立/選分層包/刪除列; 「全部拆解」與各重跑照常(金色付費按鈕、價錢、進度列)
  - 渲染: 同渲染頁, 拿掉分層包選單; 配方讀取/存檔照常(共用配方); 工具列多一顆主要按鈕「設為輸出」
- 切換頁籤時重新載入分層包(拆解改過的圖層渲染馬上用到); 渲染參數在切頁籤時保留
- 打開時配方用節點上次設為輸出的配方, 沒有就用預設值
- 關閉時渲染參數跟輸出時不同 → 提示「渲染參數還沒設為輸出」

## 4. API

分層包單一包的路由抽成共用函式, 兩邊掛同一份:

| 前綴 | 分層包 |
|---|---|
| `/api/packs/{name}` | 拆解檢查的分層包(原本) |
| `/api/flows/{flow}/nodes/{id}/style` | 改風格節點的分層包(節點種類不是 style 回 400) |

共用的子路由: `GET ""`、`GET /files/{layer}.png`、`POST /steps/{step}`、`POST /decompose`、`PUT /layers/{layer}`、`GET /region`、`PUT /regions/{id}`

節點另加:

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `.../style/status` | `{exists, inputRev}` |
| POST | `.../style/init` | 以上游輸出建立(已存在就整個重建), 記 `inputRev`; 上游沒有輸出 400 |

## 5. 前端

- `api.ts`: 單一分層包的呼叫抽成 `packApi(base)`; `api` 本身沿用(分層包名組網址), `api.flows.style(flow, id)` 用節點網址
- `gl/renderer.ts` 的 `loadPack` 吃檔案網址函式
- `decomposePage.ts`、`renderPage.ts` 各多一個嵌入模式
- `flow/editors/styleEditor.ts`: 建立/重建分層包、兩個頁籤、設為輸出
- 進行中 AI 工作的識別與其他節點相同(`flow:<流程>:<id>`), 返回流程不中斷、節點轉圈

## 6. 限制

- 渲染結果沒有透明背景(分層包的原圖本來就鋪白底)
